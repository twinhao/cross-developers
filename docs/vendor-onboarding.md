# 廠商接入所需資料

沒有指定機型也可先跑 [快速開始](quickstart.md)，驗證 API 與事件去重。實機 adapter 先以一家廠商、一款設備、一種量測流程開始。

請提供以下最小資料，不需真實病人紀錄：

| 項目 | 廠商填寫內容 |
|---|---|
| 廠商／設備 | 名稱、機型、韌體版本、設備識別方式 |
| 連線方式 | BLE／Wi-Fi／USB／廠商 SDK；是否需手機閘道 |
| 規格資料 | SDK、封包說明及可公開分享的合成原始封包 |
| 量測格式 | 類型、導程數與名稱、取樣率、數值格式、單位 |
| 校正與處理 | ADC 至物理單位的轉換、增益／偏移、濾波與掉包標記 |
| 時间與事件 | 設備時鐘、時區、事件 id、斷線後能否取回原片段 |
| 實際工作流程 | 誰使用、何時量測、如何識別病人與設備、資料要送到哪裡 |
| 接收方 | 先用原生 API，或已有 HIS／FHIR profile 與指定版本 |

## 第一個共同驗收流程

以廠商提供的合成封包，確認來源與物理單位，再測一筆事件的接收、保存、讀回及顯示。接著演練斷線、重送、App 重開與內容衝突；驗證同一事件不重複保存、錯誤不被默默丟棄。

初期記錄接入花費時間、首次上傳成功率、補傳結果與人工處理次數。實際試點再依工作流程建立量測分母與觀測時間，不在缺少試點資料時承諾效率百分比。

FHIR／TW Core／健保交換需求需包含接收方的具體 profile、版本、驗證工具及接收流程。只有「需要 FHIR」不足以決定實作方式；原生資料接收可先驗證。
