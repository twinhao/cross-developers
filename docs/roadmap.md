# 交付路線

狀態：2026-10-09。以下是交付順序，不是已提供功能或確定日期的承諾。

| 階段 | 可交付結果 | 狀態／完成條件 |
|---|---|---|
| 1. 原生量測沙盒 | 心率／合成 ECG API、原生 App 保存與讀回核對 | 已完成本機驗證 |
| 2. 開發者文件包 | 獨立參考服務、OpenAPI、兩種語言範例與接入資料 | Developer Preview 0.3.0，MIT 授權 |
| 3. 開發者入口 | 官網產品定位、快速開始與文件導覽、公開文件庫 | 文件庫發布；網站本機預覽，尚未部署 |
| 4. 正式資料邊界 | 租戶、設備憑證、病人配對與原生資料保存 | 待實作，完成隔離與授權驗證後才進實際資料試點 |
| 5. 首個設備 adapter | 一家廠商／一個機型的連線與封包解析 | 待取得規格及合成封包 |
| 6. 共同試點 | Design Partner 的完整工作流程與量化結果 | 目標 3–5 家，先確定第一個驗證場景 |
| 7. 指定系統交換 | Webhook、HIS 或 FHIR／TW Core adapter | 按接收方與試點需求排序，不一次建全部 |

## 產品原則

- Cross 連接既有設備與系統；預約保留為參考應用，Marketplace 為附加能力。
- 不做 LINE-first，預約可以直接走 Web；設備流程按需求使用共用 App。
- Cross 原生資料是本階段主資料，FHIR 是交換邊界；現階段不引入完整 FHIR server。
- 不先堆疊 AI 功能。先證明資料可靠接入與工作流程有改善，再選擇分析功能。
- 文件與官網只列出已驗證能力；規劃能力要標示狀態。

## 試點指標

設備場景記錄接入時間、事件接收／補傳結果、資料衝突與人工處理次數。預約場景仍記錄預約完成率、No-show rate、行政工時與人工處理次數。

每個試點先記錄現況，定義量測方式，再比較導入後結果。沒有改善的流程優先修改，不以功能數量替代成效。
